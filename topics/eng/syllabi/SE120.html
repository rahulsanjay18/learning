Course description

System design and ML system design at the depth expected of a staff engineer. We read Kleppmann's Designing Data-Intensive Applications (2nd ed.) for data systems and Huyen's Designing Machine Learning Systems for ML. Each topic is applied to a real design for your 3D chess platform: the move relay, matchmaking, the analysis job queue and the database. Your placement showed this is where to put extra effort, so the course is the longest in the staff track. The deliverable is three written designs, one of them an ML system, each covering requirements, trade-offs, failure modes and a migration plan.

Learning objectives

By the end of this course you can:

  1. Turn vague requirements into functional and nonfunctional requirements with numbers (latency, throughput, availability).
  2. Choose data models and storage engines and defend the choice.
  3. Design replication and sharding for a given workload and explain the consistency you get.
  4. Explain transactions, isolation levels and the failure modes of distributed systems, and design around them.
  5. Design batch and stream processing pipelines.
  6. Design an ML system end to end: data, features, training, serving, monitoring and retraining.
  7. Write a migration plan that keeps the system running.

Texts

  • Required (in your library): Huyen, Designing Machine Learning Systems (O'Reilly, 2022): Chapters 2 "Introduction to ML Systems Design", 7 "Model Deployment and Prediction Service", 8 "Data Distribution Shifts and Monitoring", 9 "Continual Learning and Test in Production".
  • Recommended (to buy): Xu, System Design Interview, Volumes 1–2; Aminian and Xu, Machine Learning System Design Interview.
  • Optional (in your library): Takada, Distributed Systems for Fun and Profit.
